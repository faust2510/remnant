# V2 数据契约（供子代理并行施工，先读这一份再动手）

所有内容都在 `data/*.json`。JSON 必须：UTF-8、2 空格缩进、无尾逗号、顶层是一个对象（用 `python3 -m json.tool` 校验）。
**代码只认下面列出的键**；未知键会被忽略（可安全地当注释用），但**不要改已有键的名字或类型**。

## 1. 通用约定

- 所有 `id` 用小写下划线 ASCII；中文只出现在 `name` / `desc` / `scripture`。
- `scripture` 写经文出处，如 `撒上 17:40`。
- 颜色写 `#RRGGBB` 字符串。
- `max_level` 一律 5。
- 数值取整数或一位小数；不要写字符串数字。

## 2. 行为与状态（代码已实现，不能新增）

- `behavior`: `line_projectile` | `arc_melee` | `orbit` | `zone` | `homing`
- `status`: `""` | `burn` | `tremor` | `blind` | `wet` | `fear`
- `modifier`（仅祝圣武器）: `shockwave_on_hit` | `tidal_push` | `wall_push` | `trail_fire` | `holy_smoke` | `echo_blade`

## 3. `data/weapons.json`

```json
{"weapons": [{"id","name","scripture","behavior","status","color",
  "max_level":5,
  "params":{"damage","speed","pierce","cooldown","range","count","spread_deg","size"},
  "scaling":{"damage","cooldown","range","count"},
  "overrides":{"3":{...},"5":{...}}}]}
```

- `params` 里没用的键可以省略（`arc_melee` 用 `range` 当锥长、`arc_deg` 为锥角；`orbit` 用 `count`/`radius`/`tick`；`zone` 用 `radius`/`duration`/`tick`；`homing` 用 `speed`/`count`/`range`）。
- `scaling` 是每级相对基线的乘法增幅（例：`damage: 0.32` = 每级 +32% 基线）。

## 4. `data/fusions.json`

```json
{"fusions": [
  {"id","type":"weapon_passive","name","scripture","weapon","passive",
   "behavior","status","params":{...},"scaling":{...},"overrides":{...},
   "modifier","evolves_to":{"name","scripture","level":5,"overrides":{"damage":1.25,...}}},
  {"id","type":"dual_weapon","name","scripture","weapons":["a","b"],"behavior","params":{...}}
]}
```

- `weapon_passive`：`weapon` 指基础武器 id，`passive` 指宝物 id；一件基础武器**只能有一条** `weapon_passive` 配方（代码按 weapon 建索引）。
- `dual_weapon`：`weapons` 为两件基础武器 id。

## 5. `data/passives.json`（宝物，20 件）

```json
{"passives": [{"id","name","scripture","kind":"fruit|armor|treasure","stat":"<见下>","per_level","max_level":5,"desc"}]}
```

`stat` 已支持的取值：`lifesteal` `xp_gain` `damage_reduction` `armor` `pickup_radius` `crit_chance` `dot_damage` `move_speed` `cooldown` `damage_pct` `max_hp`。
新增 `stat` 需要引擎底座同步实现（本轮由 D 代理加：`area_pct` `projectile_speed` `duration` `knockback` `crit_damage` `heal_per_sec` `silver_gain` `enemy_speed_slow`）。
`kind`：`fruit`（圣灵九果，进升级池）| `armor`（全副军装，精英掉落）| `treasure`（会幕宝物，进升级池与祝圣配方）。

## 6. `data/characters.json`（见证人，20 位）

```json
{"characters": [{"id","name","scripture","hp","speed","weapon","desc",
  "perk":{"<key>":<value>},"awakening":{"name","desc","perk":{...}},
  "unlock":{"stage":"ch01_eden","silver":100,"note":"..."}}]}
```

`perk` 已有键（代码会读）：`crit_chance` `aim_crit_mult` `knockback_mult` `hit_push` `weapon_slots` `damage_per_empty_slot` `move_shockwave`。
`perk` 新增键（由 D 代理实现）：`max_hp_bonus` `damage_taken_mult` `projectile_speed` `duration_mult` `pickup_bonus` `level_heal_bonus` `melee_only_bonus` `burn_stack_max` `silver_bonus`。

## 7. `data/enemies.json`（普通敌人 24 + 精英 12）

```json
{"enemies": [{"id","name","hp","speed","damage","radius","xp","color",
  "behavior":"chaser|ranged|dive|charger|boss","elite":true,"elite_affix":"..."}]}
```

`behavior` 只能是这 5 种（代码实现）。`elite` 缺省 false；`elite_affix` 本轮只做说明文字，不驱动机制。

## 8. `data/stages.json`（24 章）

```json
{"stages": [{"id","name","scripture","chapter":1,"duration":750,"boss_at":660,
  "budget":{"base","per_minute","max_alive"},
  "mix":[{"t":0,"enemies":[{"id","w"}]}],
  "elites":[{"t":150,"id":"six_finger_giant","n":1}],
  "boss":"<bosses.json 的 id>",
  "ground":{"base","speckle","zone","rocks":true},
  "mods":{"cooldown":0.9,"enemy_speed":1.12,"shillings":1.25},
  "mechanic_id":"eden_fall","desc":"一行玩家可见描述","unlock_wins":0}]}
```

- `elah_valley` 与 `judea_wilderness` 这两个 id **必须保留并继续存在**（存量存档与命令行依赖），分别算第 13、17 章。
- 其余章节 id 用 `ch01_eden` 这种 `chNN_slug` 形式。
- `mechanic_id` 取值固定 8 个之一：`eden_fall` `flood_tide` `babel_confusion` `altar_charge` `plague_cycle` `sea_walls` `lightning_zones` `bitter_water` `wall_ring` `darkness_lamp` `burnable_field` `cave_choke` `dry_creek` `drought_fire` `belly_shade` `furnace_rings` `temptation_choice` `storm_push` `pentecost_rush` `prison_quake` `seven_lamps` `abyss_vents` `meteor_horde` `glass_sea`（共 24 个，一章一个，代码按名字分发）。

## 9. `data/bosses.json`（新文件，24 位 BOSS）

```json
{"bosses": [{"id","name","scripture","hp","speed","damage","radius","xp","color",
  "phases":[
    {"at_hp":1.0,"skills":[{"id":"ring_burst","cd":2.4,"params":{"count":10,"damage":9}}]},
    {"at_hp":0.66,"skills":[{"id":"summon","cd":9.0,"params":{"enemy":"raven","n":6}}]},
    {"at_hp":0.33,"skills":[{"id":"charge","cd":6.0,"params":{"damage":22}}]}]}]}
```

`skills[].id` 只能取这 8 种（代码实现）：`ring_burst`（环形弹）`aimed_shot`（三连点射）`summon`（召唤）`charge`（冲锋）`zone_denial`（地面留坑）`heal_self`（回血）`spawn_totem`（放图腾，需打掉）`nova`（贴身爆）。

## 10. `data/relics.json`（新文件，12 件圣物）

```json
{"relics": [{"id":"R01","name","scripture","unlock":{"stage":"ch01_eden","wins":1},"effect":"codex","desc","note"}]}
```

`effect` 只能取（代码实现）：`codex`（图鉴）`dps_meter` `fast_forward` `covenant_system` `banish` `jukebox` `endless` `reroll_plus` `chest_double` `silver_magnet` `seal_shop` `all_treasures`。

## 11. `data/covenants.json`（新文件，16 张约）

```json
{"covenants": [{"id","name","scripture","rarity":1,"text":"一句话规则",
  "effects":[{"key":"damage_mult","value":0.25}]}]}
```

`effects[].key` 允许：`damage_mult` `cooldown_mult` `area_mult` `projectile_speed` `crit_chance` `crit_damage` `max_hp` `armor` `lifesteal` `xp_gain` `silver_gain` `move_speed` `knockback_mult` `status_on_hit`（`value` 写状态名，如 `burn`）、`extra_projectile`（整数）。

## 12. `data/achievements.json`（新文件，40 项）

```json
{"achievements": [{"id","name","desc","cond":{"type":"kills_total","value":10000},"reward":{"silver":100,"relic":"R02"}}]}
```

`cond.type` 允许：`kills_total` `kills_in_run` `stage_clear` `stage_clear_seal` `no_damage` `elite_kills` `fusion_count` `level_reach` `survive_time` `weapon_only`（`cond.value` 可为字符串）。

## 13. 施工纪律

1. **只改自己名下的文件**；需要别人文件的新键，写进 `docs/V2-接口需求-<你的名字>.md`，不要直接改。
2. 改完必须跑 `python3 -m json.tool <file> > /dev/null`，并自查：武器引用的被动 id 存在、祝圣引用的武器 id 存在、`stages` 引用的敌人/boss id 存在。
3. 只能跑 `--headless` 的 Godot 命令，**禁止** `open`、`--shot` 之类的窗口命令（会弹出游戏窗口影响用户）。
4. 数值要能玩：1 印下 BOSS 血量约等于「玩家 40 级时的 30–50 秒输出」，不要写出一发打死或打不动的数字。
5. 在 `docs/V2-数据-<区域>.md` 里写清楚：做了什么、数量、验证命令与结果、给别人的接口需求。
