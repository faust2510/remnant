| API | 返回 | 说明 |
| --- | --- | --- |
| `setup(character_id, bonus={}, relic_ids=[])` | void | 第三个参数不传时自动从 Meta.relics 拉取 |

| `perf(key, default)` | Variant | 角色 perk + 觉醒 perk 合并：数值相加、`*_mult` 相乘、非数值覆盖 |
| `incoming_damage_mult()` | float | (1 - 总减伤) × damage_taken_mult |
| `silver_mult()` | float | `stats.silver_mult` |

新 stat 与旧键的镜像关系（**旧系统只认旧键，所以必须同步**）：

| 新键 | 计算 | 镜像到的旧键 |
| --- | --- | --- |
| `area_pct` | 被动累加 | `area_mult *= 1 + area_pct` |
| `projectile_speed` | 被动/ perk 相乘 | `proj_speed_mult *= projectile_speed` |
| `knockback` | 被动累加 | `knockback_mult *= 1 + knockback` |
| `crit_damage` | 被动累加 | `crit_mult += crit_damage`（基础 1.6） |
| `pickup_bonus` | perk 累加 | `pickup_radius *= 1 + pickup_bonus` |
| `max_hp_bonus` | perk 累加 | `max_hp += max_hp_bonus` |
| `level_heal_bonus` | perk 累加 | `level_heal = 0.15 + 元强化 + level_heal_bonus` |
| `silver_gain` / `silver_bonus` | 被动 / perk | `silver_mult = (1+silver_gain)*(1+silver_bonus)` |
| `duration` | 被动 × / perk `duration_mult` × | 无旧键，新系统直接读 |
| `heal_per_sec` | 被动累加 | 无旧键，run.gd 每帧回血 |
| `enemy_speed_slow` | 被动累加 | 无旧键，clamp 0..0.8，敌人侧消费 |
| `damage_taken_mult` | perk 相乘 | clamp 0.05..4.0 |
| `melee_only_bonus` / `burn_stack_max` | perk 累加 | 由 combat 侧按行为类型消费 |

## 四、21 阶灾变与 seal_mult

- `tier 1–7`（七印）：`seal_mult = 1.0 + 0.3 × (tier - 1)`，即 1.00 / 1.30 / 1.60 / 1.90 / 2.20 / 2.50 / **2.80**，与旧存档逐位一致。
- `tier 8–21`（七号 / 七碗）：`p = (tier-7)/14`，`ease = p²(3-2p)`，`seal_mult = 2.80 + 0.40 × ease`，21 阶正好 **3.20**，中间严格单调。
- 敌 HP / 敌伤 / 刷怪沿用七印斜率线性叠加：21 阶 = 2.80 / 2.20 / 1.80（每阶 +9% / +6% / +4%）。
- `effective_tier()`：`tier > 7` 用 `tier`，否则用 `selected_seal` —— 因为营地面板只写 `selected_seal`，这样老入口仍然正确。
- `max_tier_allowed()`：默认 7；持 `seven_seals_scroll`（别名 `R11`）后 21。`register_run` 解锁下一印时不会越过这个上限。

## 五、老存档兼容

存档 `user://save.json`，`Meta.SAVE_VERSION = 2`。读取时每个 v2 键都有默认值：

| 键 | 老存档缺省 | 规则 |
| --- | --- | --- |
| `version` | 不写 | 只写不读，向前兼容 |
| `tier` | `selected_seal` | 老存档等值迁移，1–7 语义不变 |
| `relics` | `[]` | 只保留字符串、去重 |
| `achievements` | `[]` | 同上 |
| `awakened_ids` | `[]` | 同上 |
| `buildings` | 由已买强化等级派生 | 每次 `load_save` / `buy` 都会 `_sync_buildings()` |

读档时不认识的键忽略、类型不对的键回退默认（`levels` 非字典 → 全 0），越界值一律 clamp。**没有 v2 键的存档已验证可正常读入并继续写回。**

## 七、遗留问题 / 待别人接线

1. `faith`（信心）、`prayer`（祈祷）、`sanctuary`（恩膏重随）三项强化**没有实装**：`Meta.UPGRADES` 只有 6 项，因为营地面板 `ROW_Y0=64 / ROW_STEP=31 / 高度 360` 放不下 9 行（9 行会溢出到 401 > 360）。数值已按圣典写进 `data/store.json`（`live:false`），面板改造后可 3 行内接上。
2. `data/relics.json`、`data/covenants.json` 目前还不存在（数据组负责），引擎侧已静默降级；`relics` 支持可选的 `"stats": {键: 值}` 字段直接叠属性。
3. 七号/七碗（8–21 阶）的 `mods`（视野 -25%、落石、双 BOSS、同屏 750 …）只是数据，**没有系统消费**——需要 `src/sim`/`src/combat` 侧接线。
4. 结算要传真实阶：`Meta.register_run(..., seal)` / `reward_for(..., seal)` 的 `seal <= 0` 时用 `effective_tier()`，但 `--seal=N` 命令行跑局必须显式传 N，否则倍率与实际难度不符。
5. 七碗每阶「银两再 +20%」是我按 2.80→3.20 曲线落定的（圣典只给了七号 +25% 与终局 3.2 倍），已写进 `store.json` 的 `silver_step_bowl = 0.20`，**待策划确认**。
6. 觉醒点亮没有自动钩子：3 印通关后需要调用 `Meta.set_awakened(cid)`（属于 run.gd / 结算界面，不在我的文件里）。
7. `GameState.is_awakened()`（无参，读当前角色）与 `Meta.is_awakened(cid)`（带参）同名不同签名，调用时注意区分。
