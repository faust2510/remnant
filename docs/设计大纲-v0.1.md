# 《余民》设计大纲 v0.1

> 文档状态：草案，供外部评审（Gemini）优化

> 引擎：Godot 4.7.1（GDScript，2D；本机无 .NET，不能用 C#）

## 0. 一句话

在末世异象中，你是“余民”的守望者；借用历代见证人的兵器抵挡属灵军兵，把两件基础武器在祭坛上祝圣成更强的兵器，赶在“兽的先锋”到来前点亮成全。

## 2. 定位与边界

- 参考坐标：Vampire Survivors 的骨架（自动攻击、经验、升级暂停、压力曲线），加上自创的祝圣/祭坛系统。
- 目标体验：12 分钟内从“只能跑”到“满屏清场”，中途至少完成 1–2 次祝圣、接近 1 次成全。
- 目标玩家：喜欢幸存者类、对圣经故事有认知或好奇的玩家；不做宣教产品，不做宗教仪轨模拟。
- 三条定位红线：
  1. 不扮演耶稣、不描绘神格；神迹作为背景与恩赐，不作为可操控角色。
  2. 敌人是“属灵军兵”（弗 6:12），不把现实民族画成待屠杀的怪物；歌利亚这类个体可以作 BOSS。
  3. 风格化、不血腥；圣物不做抽卡、不做付费赌注。
- 首版不做：手机触屏、联机、多语言（先中文，英文留接口）、创意工坊、内购。

## 3. 世界观与叙事框架

- 末世异象（启示录框架）：空中掌权者的军兵倾巢而出，地上只剩少数持守的人——“余民”（罗 11:5）。
- 云彩般的见证人（来 12:1）：历代圣徒以异象形式与你同站。这是“不同时代角色同场”的叙事许可，也是武器与恩赐的来源。
- 每局是一场“试炼”，从圣经中的某个场景抽取（第一章：以拉谷）。试炼结束回到“守望之地”（局外主菜单）。
- 局外难度阶梯用“七印”命名，每印追加一个全局词条（如饥荒=治疗掉落减少，战争=敌人移速 +10%，死亡=复活次数 -1）。

## 4. 核心循环

| 层级 | 玩家在做什么 | 设计变量 | 失败点 |
|---|---|---|---|
| 秒 | 走位、引怪、拾取 | 移速、拾取半径、受击反馈 | 手感不跟手 |
| 分钟 | 领受三选一、祝圣 | 武器×被动乘区、配方 | 选择无意义 |
| 单局 | 撑到 BOSS 并击败 | 刷怪预算、祭坛时点、精英密度 | 曲线太平或太陡 |
| 局外 | 花舍客勒解锁 | 解锁内容 > 永久数值 | 数值稀释技术 |

核心张力：怪物压力随时间指数上升，玩家成长靠“领受 + 祝圣 + 成全”三段跳；每一段都要有可见的质变，而不是纯数值堆叠。

## 5. 构筑系统

### 5.1 基础武器（6 件，每件 5 级）

| 武器 | 出处 | 行为 | 手感定位 | 升级方向 |
|---|---|---|---|---|
| 投石索 | 撒上 17:40 | 直线穿透石弹 | 远程单体、穿透 | 伤害、弹速、穿透数 |
| 牧杖 | 出 14:16；诗 23:4 | 扇形横扫 | 近战控场、击退 | 范围、击退、伤害 |
| 号角 | 书 6:4；士 7:16 | 锥形音波 | 击退、破防 | 锥角、击退、冷却 |
| 火把 | 士 7:16；15:4 | 环绕火焰 | 近身持续 | 半径、转速、灼烧 |
| 香炉 | 利 16:12；启 8:3 | 落点烟云 | 区域持续、减速 | 云半径、持续时间 |
| 琴 | 撒上 16:23 | 追踪音波 | 自动索敌 | 弹数、追踪、伤害 |

### 5.2 祝圣（武器 × 武器）

规则：

- 两件指定基础武器 + 1 个火炭，在祭坛处祝圣为 1 件祝圣武器。
- 祝圣后两件基础武器消失，祝圣武器从 1 级重新成长（5 级）。
- 每件基础武器正好参与 2 条配方，保证“选哪件”都有两条出路。
- 祝圣武器 DPS 目标约为两件之和的 0.85 倍，但成长上限约 1.5 倍，且附带质变效果；不能做成纯亏或纯赚。
- 火炭由精英掉落，每局 4–6 个；祝圣消耗 1 个。

| 配方 | 产物 | 效果 |
|---|---|---|
| 投石索 + 号角 | 歌利亚的丧钟 | 石弹命中引发音波爆裂 |
| 投石索 + 琴 | 牧童的诗篇 | 石弹在敌群间弹跳，尾迹带音刃 |
| 牧杖 + 火把 | 燃烧的荆棘 | 横扫在地面留下不灭圣火 |
| 牧杖 + 香炉 | 会幕的云柱 | 烟云跟随玩家，减速 + 灼烧 |
| 号角 + 火把 | 耶利哥的黎明 | 音波推墙，火墙向外扩散 |
| 香炉 + 琴 | 众圣徒的祈祷 | 香云上升，治疗 + 追踪火炭 |

### 5.3 成全（终极形态，首版 3 件）

- 条件：祝圣武器满 5 级 + 本局击杀数不少于 500。
- 触发：满足条件的瞬间暂停 0.5 秒，播放演出，武器变形；不消耗材料。
- 定位：一局最多点亮 1 件；是全屏级质变，不是数值加成。

| 祝圣武器 | 成全 | 效果 |
|---|---|---|
| 耶利哥的黎明 | 城墙倾覆 | 全屏冲击波 + 眩晕 |
| 燃烧的荆棘 | 坛上不灭的火 | 全屏持续火海（利 6:13） |
| 众圣徒的祈祷 | 金坛的倾倒 | 火炭从天而降（启 8:5） |

### 5.4 被动：圣灵的果子（8 项，每项 5 级）

| 果子 | 每级效果 | 出处 |
|---|---|---|
| 仁爱 | 击杀回复 1% 最大生命 | 加 5:22 |
| 喜乐 | 经验获取 +10% | 加 5:22 |
| 和平 | 受到伤害 -6% | 加 5:22 |
| 忍耐 | 护甲 +2、抗击退 | 加 5:22 |
| 恩慈 | 拾取半径 +20% | 加 5:22 |
| 良善 | 暴击率 +5% | 加 5:22 |
| 信实 | 持续伤害 +12% | 加 5:22 |
| 节制 | 冷却时间 -6% | 加 5:23 |

### 5.5 领受（升级三选一）

- 每次升级暂停世界，抽 3 张卡：可升级武器、可升级被动、未拥有的武器、未拥有的被动。
- 动态池：满级、已祝圣的旧武器自动移出；祝圣武器与成全武器加入。
- 权重草案：已持有武器的升级 45%，新武器 20%，被动 35%。
- 首版不做重随、不做跳过；卡面显示经文出处。

### 5.6 装备位

- 4 个武器位、3 个被动位。
- 起手 1 件武器；祝圣消耗 2 件、产出 1 件，净空出 1 位——这是祝圣的核心取舍。
- 被动不参与祝圣。

## 6. 祭坛（地图事件）

- 刷新：3:00 / 6:00 / 9:00 各出现一座；同时只存在一座；精英死亡有概率提前刷新。
- 交互：靠近后按键进入暂停界面，只显示“当前持有武器能凑出的配方”。缺件配方灰显并标注缺哪件。
- 界面结构：左=当前武器，右=可祝圣结果预览（效果、预计 DPS 变化、消耗），底部=确认。
- 使用后祭坛熄灭；未使用的祭坛保留到下一座刷新，不强制。
- 设计意图：把“合成”从菜单变成地图上的目标点，制造节奏呼吸与路线决策。
- 风险：暂停界面打断战斗节奏；首版需限制信息量。

## 7. 敌人与 BOSS（第一章：以拉谷）

敌人不是“非利士人”这个民族标签，而是歌利亚在撒上 17:44 亲口召唤的“空中的鸟、田野的兽”，加上异象化的军兵与巨人。

| 敌人 | 生命 | 移速（格/秒） | 伤害 | 经验 | 行为 |
|---|---|---|---|---|---|
| 军兵 | 18 | 2.2 | 6 | 1 | 直线追击，接触伤害 |
| 弓手 | 14 | 1.8 | 8 | 2 | 保持 6–8 格，射箭 |
| 乌鸦 | 10 | 3.6 | 5 | 2 | 飞行，盘旋后俯冲 |
| 野兽 | 40 | 2.8 | 12 | 4 | 短距蓄力冲锋 |
| 巨人（精英） | 300 | 1.4 | 18 | 25 | 践踏冲击波，掉火炭 |
| 歌利亚（BOSS） | 4000 | 1.2 | 25 | — | 三阶段 |

歌利亚三阶段：

- P1：投矛（直线）+ 践踏（圆形冲击波）。
- P2（70%）：召唤乌鸦群 + 军兵方阵。
- P3（35%）：狂暴，移速与攻速上升，地面出现裂缝预警。

## 8. 场景与视听

- 场景：以拉谷，黄昏，沙岩地面、枯树、立石、远山剪影。边界用山壁与雾，不用硬墙。
- 分辨率：基准 640×360，16×16 像素素材，3× 缩放；窗口 1280×720 起。
- 调色板：沙岩 #C9A66B、暗蓝 #1B2A41、血红 #7A2E2E、烛金 #E0B85A、骨白 #E8E2D0。
- 字体：Noto Serif SC（OFL），标题用石刻质感，正文简洁。
- 音效：号角、钟、低音 drone、无歌词的圣咏式和声；首版用占位音，不做完整配乐。
- 素材策略：Kenney Tiny Dungeon（石墙/地穴/骷髅）打底；沙漠、帐篷、巨人等优先 OpenGameArt CC0；缺的用程序化占位，登记 CREDITS.md。

## 9. 局外 Meta

- 货币：舍客勒。结算来源：击杀数、存活时间、首次祝圣、首杀 BOSS、首次成全。
- 解锁：见证人（角色）、基础武器、七印难度、图鉴条目。永久数值加成只做“小幅”（不超过 10%），避免稀释技术。
- 图鉴：配方、敌人、经文；首次祝圣给额外舍客勒。
- 存档：user://save.json，带版本号与迁移函数；单局进度不存档（Roguelite 规则）。

## 10. 手感与表现层

- 移动：8 向，带轻微加速度与摩擦；首版不做冲刺（留给后续角色/解锁）。
- 受击：0.5 秒无敌帧、角色闪烁、屏幕震动 2px、hitstop 30–50ms。
- 拾取：磁吸；经验宝石按价值分 3 档颜色；治疗与舍客勒单独音效。
- 伤害数字：限流与合并，避免满屏；暴击加大加色。
- 死亡：慢镜 0.3 秒 + 结算面板；重开不超过 3 次点击。
- 升级/祭坛：暂停世界，UI 立即可操作；键盘 1/2/3 与鼠标均可选。

## 11. 数值框架（草案，全部待模拟验证）

- 单位：1 格 = 16 原始像素；玩家移速 4.5 格/秒。
- 玩家：生命 100，护甲减伤 = 护甲 / (护甲 + 50)。
- 伤害：DMG = (基础 + 2 × 武器等级) × (1 + 被动百分比之和) × 暴击倍率 × 武器系数。
- 敌人成长：生命 = 基础 × (1 + 0.10 × 分钟)，伤害 = 基础 × (1 + 0.06 × 分钟)。
- 经验：need(n) = 5 × 1.15^(n-1)；目标 12 分钟 25–30 级。
- 刷怪：每分钟预算 = 8 + 4 × 分钟；同屏上限 400；精英 2:30 / 5:30 / 8:30；BOSS 11:30。
- 祝圣收益下限：DPS 不低于两件之和的 0.85 倍；成全为全屏级，不计入常规 DPS。
- 以上全部用无头模拟跑 3 组种子验证，不靠拍脑袋。

## 12. 技术架构

- 引擎约束：Godot 4.7.1，GDScript，2D；本机无 .NET；中文路径下统一先 cd 再用相对路径。
- 目录草案（res://）：
    data/            武器、配方、被动、敌人、波次、章节 JSON
    scenes/          main、run_root、world、player、ui
    src/core/        状态机、事件、数据加载、存档
    src/combat/      行为原子、伤害、投射物
    src/entities/    敌人管理、拾取、玩家控制
    src/ui/          HUD、领受、祭坛、结算、图鉴
    tools/           sim_run.gd 无头模拟
    assets/vendor/   CC0 素材与 CREDITS
- 实体管理：敌人用 SoA 数组（位置/生命/速度/状态/类型），集中在 EnemyManager；节点只做表现，对象池复用；碰撞用圆形距离 + 均匀网格空间哈希（4 格一格），敌人不参与物理引擎。
- 渲染：首版 Sprite2D + 对象池；渲染接口抽象，同屏超过 600 或帧率不达标时切换 MultiMesh 后端。
- 武器原子：arc_melee / line_projectile / zone / orbit / homing 五类；祝圣武器 = 主原子 + 副效果（shockwave / trail / aura），不写 15 套独立逻辑。
- 数据示例（weapons.json）：
    {
      "id": "sling",
      "name": "投石索",
      "scripture": "撒上 17:40",
      "behavior": "line_projectile",
      "params": { "damage": 6, "speed": 12, "pierce": 1, "cooldown": 0.8 }
    }
- 数据示例（fusions.json）：
    {
      "id": "goliath_knell",
      "name": "歌利亚的丧钟",
      "requires": ["sling", "horn"],
      "material": "coal",
      "behavior": "line_projectile",
      "modifier": "shockwave_on_hit",
      "evolves_to": "walls_fall",
      "evolve_condition": { "level": 5, "kills": 500 }
    }
- 单局状态机：Menu → Run → LevelUp / Altar（暂停）→ Boss → Result。
- 暂停：get_tree().paused = true，UI 节点 process_mode = ALWAYS；恢复时统一走一个 resume 函数，避免漏恢复。
- 无头门禁（每批改动一次跑完）：
    Godot --headless --path . --import
    Godot --headless --path . --check-only --script <改动脚本>
    Godot --headless --path . --quit
    Godot --headless --path . --script res://tools/sim_run.gd --fixed-seed 1 --minutes 12
- 模拟输出：击杀数、等级、祝圣次数、成全时间、受伤曲线、同屏峰值；作为平衡与回归依据。
- 性能目标：60fps @ 400 敌人 + 200 投射物 + 300 拾取；掉帧优先降同屏上限与特效数量。

## 14. 里程碑（估算，供排期）

- M0 骨架：项目设置、数据加载、状态机、无头门禁、占位场景。3–5 天。
- M1 5 分钟切片：走位、投石索、军兵/乌鸦、经验、领受、第一座祭坛。5–8 天。
- M2 完整单局：6 基础 + 6 祝圣 + 3 成全、3 祭坛、歌利亚、结算、存档。10–15 天。
- M3 打磨：手感、音效、平衡、图鉴、七印雏形、性能。持续。

验收标准（每个里程碑都要满足）：

- 连续 3 局不崩；无脚本错误。
- 目标帧率达标；同屏峰值可复现。
- 无头模拟通过；关键数值有记录。
- 录屏/截图自检：真的看过画面再宣布完成。
