## 1. 数值解算口径（为什么 Lv.5 和圣典对得上）

代码的取值规则是 `value(lv) = base * (1 + scaling * (lv-1))`，`overrides["N"]` 直接覆盖该级。

- **伤害**用圣典的「每级 +X%」原值：20 把武器、20 条祝圣、6 条合鸣的 **Lv.5 伤害与圣典表格逐个对齐**（误差 < 0.05）。
- **冷却/半径/射程/击退**：圣典同时给了「每级 %」和「Lv.5 终值」但两者不总自洽（例：投石索 0.80 与「-7%/级」→0.576，圣典终值写 0.62）。取舍是**终值优先**：`scaling` 按终值反解（保留 0.056 级别的精度），或在 `overrides["5"]` 里钉死终值。
- **弹数/穿透/盏数**这类离散量一律走 `overrides`，并**逐级补齐**（Lv.2/3/4 都不会掉档）。这一点修掉了旧文件的隐性 bug：旧 `sling` 只有 `"3"` 和 `"5"` 覆写，Lv.4 会掉回 1 颗石子。

## 7. 遗留问题与接口需求（已写入 `docs/V2-接口需求-data-weapons.md`）

1. **T16 馨香乳香 / T19 细麻衣 的 stat 是占位**。圣典效果分别是「投射物数量 +1（2 级封顶）」和「闪避无敌帧 +0.03s/级」，契约第 5 节枚举里没有对应 stat。为了守住「stat 只能取枚举」这条铁律，本轮用 `projectile_speed 0.10` 与 `duration 0.03` 占位，`desc` 里写明原案；等引擎加 `extra_projectile` / 无敌帧 stat 后换回。
2. **`evolves_to.overrides` 目前不生效**。`game_state.try_ascend()` 只把 `ascended` 置 true，`weapon_runner._ascend_params()` 用的是固定倍率（伤害 ×1.25、弹数 +1、半径/射程 ×1.12）。契约要求成全后吃 `evolves_to.overrides`（F01 弹数恒 5 + 穿透 +4、F04 锥角 360°……），需要引擎合并这个字典。
3. **圣典的 14 个专属 modifier 没有物理分支**（healing_halo / spring_burst / rhythm_haste / harvest_pull / word_pierce / spirit_beam / serpent_totem / fire_wake / stone_barrier / royal_edict / blood_cry / baptism_wave / net_drag / gate_of_light）。若要实现，得先扩契约第 2 节的枚举；本轮已按「同原子的可用 modifier」兼容挂载，机制文字保留在 `desc`。
4. **`sickle` 的负击退不生效**：`weapon_runner._arc_hit()` 只在 `kb > 0.0` 时施加击退，拾穗镰的 `knockback: -40`（回拉）实际等于不击退。
5. **`zone` 缺「以自身为中心」和 `throw_dist`**：现在无目标时固定生成在 `ppos + (0,40)`，`throw_dist` 未被读取；铃鼓 / 亚伯血环 / 香炉都受影响（铃鼓用 `range: 1` 规避索敌）。
6. **`homing` 忽略 `pierce`**：`weapon_runner` 对 homing 硬编码 `pierce: 0`，天国钥匙的穿透 2、大卫的钥匙穿透 4 在数据里但没生效。
7. **dual 的键名双写**：契约写 `weapons[]`，当前 `game_state.gd` 读 `weapon_a/weapon_b`。我两个都写，建议装载器同时接受，后续再统一。
