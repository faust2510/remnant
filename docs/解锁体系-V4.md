# 解锁体系 V4 · 兵器与宝物

> 目标：武器与被动宝物**逐步解锁**，不是开局全部可升级。开局只有 3 把兵器 + 4 件宝物，其余随「通关次数 / 累计击杀 / 灾变阶 / 见证人 / 成就」四条进度轴分批开放，让前 20 局始终有新的选项进入池子。

## 1. 数据契约

`data/weapons.json` 的每把武器、`data/passives.json` 的每件宝物都带一个 `unlock` 对象（插在 `desc` 之前，不影响既有字段）：

```json
{ "kind": "default" }
{ "kind": "wins",        "n": 3, "note": "累计通关 3 次后解锁" }
{ "kind": "kills",       "n": 800, "note": "累计击杀 800 后解锁" }
{ "kind": "seals",       "n": 5, "note": "灾变阶达到 5 阶后解锁" }
{ "kind": "character",   "id": "moses", "note": "解锁见证人摩西后开放" }
{ "kind": "achievement", "id": "ach_first_win", "note": "达成成就后解锁" }
```

- `note` 为中文条件文案（8–16 字），给营地军械库与结算页直接展示；缺省时由 Meta 按 kind 生成兜底文案。
- 老存档不需要迁移：判定只读 Meta 既有计数字段，没有新增必填键，`SAVE_VERSION` 仍为 2。
- 图标图集 `assets/icons/weapons.png` / `passives.png` 固定 160x128、5x4 格、32px/格，**行序 = 数据键序**（两处面板与 Meta 的 `unlocked_*_ids()` 都依赖这一点）。

## 2. 判定规则（src/core/meta.gd）

```gdscript
func _unlock_rule(def: Dictionary) -> Dictionary
func unlock_rule_ok(rule: Dictionary) -> bool
func unlock_rule_text(rule: Dictionary) -> String
func is_weapon_unlocked(id: String) -> bool
func is_passive_unlocked(id: String) -> bool
func weapon_unlock_note(id: String) -> String   # 已解锁返回 ""
func passive_unlock_note(id: String) -> String
func unlocked_weapon_ids() -> Array
func unlocked_passive_ids() -> Array
func unlock_snapshot() -> Dictionary            # {"weapons":[...], "passives":[...], "wins":.., "lifetime_kills":.., "seals":..}
func newly_unlocked(before: Dictionary) -> Dictionary  # {"weapons":[id..], "passives":[id..]}
```

- **纯读**：只读 `Meta.wins` / `Meta.lifetime_kills` / `Meta.seals` / `Meta.is_character_unlocked()` / `Meta.has_achievement()`，不消耗 rng、不写盘，可在 `_level_options()` 每帧调用。
- **fail-closed**：未知 kind、缺 id、n<=0、缺数据键 → 一律视为未解锁；只有 `{"kind":"default"}` 无条件解锁。
- `unlock_snapshot()` 是开局快照，`newly_unlocked(before)` 用当前解锁集与快照 diff；`before` 非法时返回空集，避免坏档崩结算。
- `is_character_unlocked(cid)`：支持 `unlock.kind = "default"`、`"achievement"`（`ach_` 前缀映射）、`"stage_clear"`（按 Meta.wins 判定），其余按默认（未解锁）处理。

## 3. 进度轴与曲线

| wins | `Meta.wins`（得胜一局 +1） | 主节奏轴，1–4 次通关放开早期选项 |

| achievement | `Meta.has_achievement()` | 预留，当前数据未使用 |

## 4. 局内接入（src/run.gd）

1. **开局快照**：`var unlock_snapshot_before: Dictionary = Meta.unlock_snapshot()`，本局全程只读。
2. **升级候选**（`_level_options()`）：
   - `new_weapon`：遍历全量武器时 `if not Meta.is_weapon_unlocked(id): continue`。
   - `new_passive`：同一分支 `if not Meta.is_passive_unlocked(pid): continue`。
   - 已拥有武器的「强化」分支不受影响（升级本来就不过滤）。
3. **见证人自带专属武器**：`characters.json` 的 `weapon` 字段在开局直接授予，即使该武器尚未在图鉴解锁也能用；这里不经过 `_level_options()`，故无需例外代码。同一把武器在本局内仍可出现在强化里。
4. **掉落与祝圣一致过滤**：`_grant_armor()`（精英军装掉落）与 `_grant_partner()`（祭坛祝圣配材）都加了未解锁跳过，避免绕过图鉴提前拿到军装/宝物——这一步超出需求书面三项，但不修会让 sim 里白拿「良善」并合成歌利亚的丧钟，破坏逐步解锁。
5. **结算汇报**：`_finish()` 在 `Meta.save_save()` 之后计算 `new_unlocks = Meta.newly_unlocked(unlock_snapshot_before)`（未提交/死亡不回写），并同时写入：
   - `rewards.set_meta("new_unlocks", new_unlocks)`
   - `rewards.flags["new_unlocks"] = new_unlocks`
   - `--sim` 时打印 `[sim] new_unlocks weapons=%d passives=%d`

结算页（`src/ui/hud.gd`，本任务范围外）读取上述键即可展示「本局新解锁」。

## 6. 营地军械库（src/camp_screen.gd）

- 营地按 **L** 打开/关闭（Esc 仍关闭；打开时方向键/WASD 移动、Tab 换栏、L/Esc 退出）。
- 标题「军械库 · 兵器与宝物」，副标题显示两栏解锁计数与「未解锁项随进度逐步开放」。
- 左栏 20 把武器、右栏 20 件宝物，均为 5x4 图标网格（`SpriteBank.weapon_icon_rect` / `passive_icon_rect`，行序 = 数据键序）。
- 已解锁：亮色图标 + 名称；未解锁：图标压暗 + 图标底部「未解锁」条 + 名称后一行红字条件（`Meta.weapon_unlock_note` 的短写）。
- 方向键移动光标，选中格金框 + 呼吸光；底部详情条显示名称 / 经文 / desc / 解锁状态（未解锁时附完整条件与进度，如「进度 · 累计击杀 300 / 800」）。
- 底部固定页脚「L 关闭 · 方向键浏览」；营地底部提示追加「L 军械库」。
- 截图参数：`--shot-camp --armory --shot-path=/tmp/armory.png`（`--armory` 不能写成 `--shot-armory`，title_screen 会把 `--shot-` 前缀路由到局内）。
- `--camp-selftest` 额外打印一行：
  `[camp] armory weapons=3/20 passives=4/20 sample=horn:累计通关 1 次后解锁 toggle=true/true/true`

## 8. 设计取舍

- **为什么不做「解锁后才进商店/图鉴」**：图鉴（V 键）仍展示全部 20 件，未解锁项在军械库中以暗色 + 条件呈现，形成「看得见的目标」，而不是隐藏内容。
- **为什么不新增存档字段**：只读既有 wins / lifetime_kills / seals，老档直接兼容；新解锁的「本局汇报」是运行时 diff，不落盘。
- **为什么用 wins 当主轴**：幸存者品类的核心循环是「再来一局」，通关次数比击杀更可控，可保证前 4 局每局都有新东西。
