# P5 · Gemini 评审修复（机制补完 / 确定性 / 数值校正）

> 起因：用户把手上的 P4 版本交给 Gemini 做了一轮 5 节评审（机制漏洞、七印曲线、地图差异化、sim 架构、README 数字矛盾），本节逐条对照源码验证并落地修复。文档只记录**这一轮真正改了代码的部分**；评审里属于「新玩法提案」的内容列在最后一节，留作 P6 候选。

## 一、祝圣三层结构：从「只改数字」变成「改机制」

### 1.1 六种 modifier 全部接线（此前只有 1 种真的生效）
原状：`src/combat/weapon_runner.gd` 里只有 `line_projectile` 读了 `modifier` 做 34px 溅射，其余五种原子完全忽略，导致 6 把祝圣武器里 5 把只是数值变大。现在：

| 祝圣武器 | modifier | 现在真的发生什么 | 落点 |
| --- | --- | --- | --- |
| 歌利亚的丧钟（投石索+良善） | `shockwave_on_hit` | 命中点 34×area 半径的溅射，溅射伤害 45% | `_fire()` line_projectile |
| 摩西分海杖（牧杖+忍耐） | `tidal_push` | 击退 ×1.6，弧形范围内敌人被推成一条缝 | `_fire()` arc_melee |
| 耶利哥的号角（号角+节制） | `wall_push` | 击退 ×1.9（城墙倾覆：整面推走） | `_fire()` arc_melee |
| 燃烧的荆棘（火把+信实） | `trail_fire` | 每次环绕结算在轨道位置落一个 r=22×area、1.1 秒的燃烧区域，把「身后留下不灭火径」变成真实地形 | `_tick_orbit()` |
| 金香坛（香炉+和平） | `holy_smoke` | 区域持续治疗 0.7 HP/s（由 `weapons.heal_pending` 每帧交给 run 结算） | `_fire()` zone + `_tick_zones()` |
| 锡安的诗篇（琴+喜乐） | `echo_blade` | 主弹后 0.22 秒再复奏一轮 55% 伤害的齐射 | `_fire()` homing + `_tick_pending()` |

### 1.2 成全（第三层）不再是「一次性礼花」
原状：`try_ascend()` 只把 `ascended` 置真 + 放一次 nova，武器形态与频率完全没变。现在：
- `_ascend_params()`：伤害 ×1.25、`count` +1、`radius`/`range` ×1.12、`arc_deg` ×1.1 —— 五类原子通吃（`_fire()` 入口统一套用）。
- 环绕武器（orbit）单独处理：轨道 +1 个、半径 ×1.12、伤害 ×1.25、结算间隔 ×0.85。
- 冷却：`tick()` 里对所有武器 `cd *= 0.82`。
- nova 保留（成全瞬间的爆发），但已经不是唯一效果。

### 1.3 成全的击杀门槛改成「成圣之后」累计
原状：`src/core/game_state.gd` 用整局 `all_kills` 比 500，中后期任何武器一到 Lv5 就立刻成全（第 2、3 把等于白送）。
现在：`apply_fusion(..., kills_now)` 把成圣瞬间的击杀数写进武器字典的 `born_kills`，条件改为 `all_kills - born_kills < evolves_to.kills`。实测 780 秒的局里仍能成全 2–3 把，但必须真的继续打。

## 二、确定性：无头模拟现在可以复现
原状：`src/sim/enemy_sim.gd`（109/266/268/269）与 `src/combat/weapon_runner.gd`（75/104/134/169）用全局 `randf()`；乌鸦摆动用 `Time.get_ticks_msec()`，而 `--sim-speed=900` 一帧跑 900 步、墙上时间几乎不动，导致模拟里的飞行轨迹和真实游玩不同。
修法：
- `EnemySim` 新增 `var rng: RandomNumberGenerator`、`var sim_time: float`（每步累加），乌鸦摆动改 `sin(sim_time * 4.0 + i)`；所有随机改 `rng.randf()/randi_range()`。
- `WeaponRunner` 新增 `var rng: RandomNumberGenerator`，暴击、散射角、弹道抖动全部走它。
- `src/run.gd` 在 `state.setup()` 之后用主 rng 派生：`enemies.rng.seed = rng.randi()`、`weapons.rng.seed = rng.randi()`。
结果：同一条命令行两次运行的结果完全一致（见验证表）。

## 三、伤害口径与七印曲线

### 3.1 被截断的 BOSS 伤害与死代码
- `minf(contact, 10.0)` → `minf(contact, 16.0)`：歌利亚 14、试探者 16 的接触伤害以前永远被削到 10，跟小兵一样疼。
- `minf(shot_dmg, 14.0)` → `18.0`：BOSS 环形弹幕单发 9 点，连吃两发就要掉血。
- 删掉 `src/run.gd:303` 的 `hit_cd = 0.6` 与 `:313` 的 `hit_cd = 0.45`：`_take_damage()` 内部第一行就把 `hit_cd` 写成 0.65，这两行是立刻被覆盖的死代码。

### 3.2 七印前 3 分钟渐入
`src/run.gd` 新增 `seal_ramp = clampf(elapsed / 180.0, 0.25, 1.0)`，血量改为 `... * (1.0 + (seal_hp - 1.0) * seal_ramp)`。7 印开局军兵是 9×1.135≈10.2 HP（1 级投石索 9 伤害 + 营地强化可击杀），3 分钟后吃满 +54%。
伤害与刷怪沿用原有口径（伤害不吃 ramp；刷怪本来就有 300 秒渐入）。

### 3.3 结算舍客勒尊重实际难度
原状：`src/core/meta.gd` 的 `reward_for()` 内部 `seal_mult()` 读的是存档里的 `selected_seal`，用 `--seal=7` 跑出来的报告却按 1 印结算。
现在：`reward_for(victory, kills, seconds, seal := -1)`、`seal_mult(seal := -1)`、`register_run(..., seal := -1)`，-1 时才回落存档值；`src/run.gd` 把真实 `seal` 传进去，通关解锁也用该印 +1。实测 7 印一局 reward 从 3096 升到 10427（2.8×），符合公式。

## 四、被动池稀释：全副军装改为精英掉落
原状：`data/passives.json` 里 9 颗圣灵果子 + 6 件全副军装混在同一个升级池，4 个被动槽被军装占掉后，4 把武器里必然有 2 把永远凑不齐配材（军装不参与任何配方）。
现在：
- `GameState` 新增 `var armor: Array`、`add_armor()`、`has_armor()`；`recompute()` 里果子和军装走同一个 `_apply_passive_def()`。
- 军装**不占被动槽**、不进升级池（`_level_options()` 里 `kind == "armor"` 直接跳过）。
- 击杀精英（`enemies.deaths[i].elite` 为真，含六指巨人与关卡里的精英兽群）自动掉落一件未拥有的军装：金色 nova + 浮字「得军装 · 救恩头盔」+ 音效。
- HUD 右下角多一行金色小字显示已获军装；底部浮字 1.8 秒淡出。

## 五、节奏与手感修正
- **首升互补**：`_level_options()` 里若 `state.level <= 2` 且只有 1 把武器，强制把三选一的第一张换成不同于当前攻击形态的 AOE 武器（orbit / zone / arc_melee）。消灭「前 5 级连抽强化与被动、画面只有一个方向的弹道」的无效局。
- **配材之光只补给快成型的武器**：`_grant_partner()` 增加 `w.level >= 3` 门槛，避免给 1 级武器提前占掉一个果子槽。
- **祭坛值不值得跑**：新增 `_altar_useful()`，除了「已能祝圣」，还包括「还能领配材」；`_auto_altar()` 与 `_altar_target()` 都改用它。此前 `available_fusions(true)` 为空就提前返回，模拟模式永远吃不到配材赠送。
- **成全提示**：成全瞬间浮字显示 `evolves_to.name`（如「成全 · 五块光滑石子」），把先前只存在于 JSON 里的名字还给玩家。
- **自动驾驶性能**：`_autopilot_dir()` 把宝石扫描提到 8 方向循环之外（原来 O(8×G)，场上几百颗宝石时每步 4000 次开方），改为每步扫一次 240px 内的宝石坐标。
- **敌人回收方向**：`_recycle_far()` 新增 `last_move_dir`，70% 投放在移动方向的侧后方扇区（追击压迫），30% 全向随机（保一条走位走廊），并且循环里不再用 `randf_range` 直接改坐标。

## 七、未采纳 / 留作 P6
- Gemini 的三套地图专属机制（干涸溪床 + 五块光滑石子 / 禁食昼夜 + 试探的石饼 / 沙暴与投石齐射）：设计很好但属于新玩法，需要单独一轮做地形带、可拾取物与 UI。
- 双武合鸣被单武祝圣「抢跑」：目前是**有意保留的取舍**（3 座祭坛 × 1 件 = 最多 3 次祝圣，先合鸣还是先单升是决策）。若要做二阶合鸣，需要新增配方与「已祝圣 + 白板」的匹配规则。
- 宝石合并（>250 颗时 10 合 1）：目前 `gems` 仍是 `Array[Dictionary]`，但自动驾驶的 O(8G) 已修；真出现卡顿再合并。
- 把 `step()` 抽成纯 `RefCounted` 的 `RunSim` 以便多线程 Monte Carlo：当前 900 倍速单线程已够用。
- **两图难度不齐**：P5 实测犹大旷野 7 印仍能 750 秒满血通关（49 级 / 10144 杀），而以拉谷 7 印默认种子 215 秒崩。旷野的 `per_minute` 只从 66 提到 70，要追平得单独调曲线，或干脆等 P6 给它专属机制。
